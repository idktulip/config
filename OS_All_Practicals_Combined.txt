AIM:
  Write a shell script to create an address book and perform the operations:
  Create, View, Insert, Delete, Modify and Exit (menu-driven, using a text
  file as the database).

SECTION 1: CODE
==============================================================================

----- addressbook.sh --------------------------------------------------------
#!/bin/bash
FILE="addressbook.txt"

while true
do
    echo "=============================="
    echo "        ADDRESS BOOK          "
    echo "=============================="
    echo "a) Create Address Book"
    echo "b) View Address Book"
    echo "c) Insert a Record"
    echo "d) Delete a Record"
    echo "e) Modify a Record"
    echo "f) Exit"
    echo "=============================="
    read -p "Enter your choice: " choice

    case $choice in

        a|A)
            # Create / clear the address book file
            > "$FILE"
            echo "Address book created successfully."
            ;;

        b|B)
            # View all records
            if [ -s "$FILE" ]
            then
                echo "----- Address Book -----"
                cat "$FILE"
            else
                echo "Address book is empty."
            fi
            ;;

        c|C)
            # Insert a new record
            read -p "Enter ID: "    id
            read -p "Enter Name: "  name
            read -p "Enter Phone: " phone
            read -p "Enter Email: " email
            echo "$id | $name | $phone | $email" >> "$FILE"
            echo "Record inserted successfully."
            ;;

        d|D)
            # Delete a record by ID
            read -p "Enter ID to delete: " id
            if grep -q "^$id |" "$FILE"
            then
                grep -v "^$id |" "$FILE" > temp.txt
                mv temp.txt "$FILE"
                echo "Record deleted successfully."
            else
                echo "Record not found."
            fi
            ;;

        e|E)
            # Modify a record by ID
            read -p "Enter ID to modify: " id
            if grep -q "^$id |" "$FILE"
            then
                read -p "Enter new Name: "  name
                read -p "Enter new Phone: " phone
                read -p "Enter new Email: " email
                sed -i "/^$id |/c\\$id | $name | $phone | $email" "$FILE"
                echo "Record modified successfully."
            else
                echo "Record not found."
            fi
            ;;

        f|F)
            echo "Exiting Address Book..."
            exit 0
            ;;

        *)
            echo "Invalid choice! Please try again."
            ;;

    esac
    echo
done

            PRACTICAL 2: fork(), wait(), ZOMBIE AND ORPHAN PROCESS       @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@       
==============================================================================

AIM:
  Write a C program in which the parent and the child both sort an array using
  fork(). Demonstrate a ZOMBIE process (child exits, parent has not yet called
  wait()) and an ORPHAN process (parent exits before the child).


==============================================================================
SECTION 1: CODE
==============================================================================

----- ex2.c -----------------------------------------------------------------
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

// --- Bubble Sort Function ---
// Simply sorts the array in ascending order
void sort(int arr[], int n)
{
    int i, j, temp;

    for (i = 0; i < n - 1; i++)
    {
        for (j = 0; j < n - i - 1; j++)
        {
            if (arr[j] > arr[j + 1])
            {
                temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}

// --- Display Function ---
// Just prints all elements of array
void display(int arr[], int n)
{
    int i;

    for (i = 0; i < n; i++)
        printf("%d ", arr[i]);

    printf("\n");
}

// --- Show Process State Function ---
// Reads /proc/<pid>/stat file to check if process is ZOMBIE (Z)
// This file exists only on Linux - stores process state info
void show_state(pid_t p)
{
    char path[64], line[256], state;
    char *s;
    FILE *f;

    // Build path like /proc/342/stat
    sprintf(path, "/proc/%d/stat", (int)p);
    f = fopen(path, "r");

    // If file not found = process already removed from process table
    if (f == NULL)
    {
        printf("Child PID %d: no process entry found (already removed)\n", (int)p);
        return;
    }

    if (fgets(line, sizeof(line), f) == NULL)
    {
        fclose(f);
        return;
    }
    fclose(f);

    // State character comes after the closing ')' in /proc/pid/stat
    // Example line: "342 (ex2) Z 341 ..." → state = Z
    s = strrchr(line, ')');
    state = (s != NULL && s[1] == ' ') ? s[2] : '?';

    printf("Child PID %d: state = %c", (int)p, state);

    // Z = Zombie → child died but parent hasn't called wait() yet
    if (state == 'Z')
        printf("  --> ZOMBIE (child has exited but parent has not called wait())");
    printf("\n");
}

int main()
{
    int n, i;
    int arr[100];

    // Take input before fork() so both parent and child get same array
    printf("Enter number of integers: ");
    scanf("%d", &n);

    printf("Enter %d integers:\n", n);
    for (i = 0; i < n; i++)
        scanf("%d", &arr[i]);

    printf("\nOriginal array: ");
    display(arr, n);
    fflush(stdout); // Flush buffer before fork() to avoid duplicate prints

    // =============================================
    // FORK() - Creates a copy of current process
    // =============================================
    // After fork():
    // pid == 0  → we are inside CHILD process
    // pid > 0   → we are inside PARENT process
    // pid < 0   → fork failed
    pid_t pid = fork();

    if (pid < 0)
    {
        perror("Fork failed");
        return 1;
    }

    // =============================================
    // CHILD PROCESS
    // =============================================
    if (pid == 0)
    {
        printf("\n--- CHILD PROCESS ---\n");
        printf("Child PID: %d\n", getpid());
        printf("Parent PID: %d\n", getppid());

        // Child got its OWN COPY of arr[] via fork()
        // Sorting here does NOT affect parent's array
        sort(arr, n);
        printf("Child sorted array: ");
        display(arr, n);

        // Child finishes and exits
        // Since parent is still sleeping → child becomes ZOMBIE here
        printf("\nChild process is terminating...\n");
        exit(0); // ← Child dies here → becomes ZOMBIE until parent calls wait()
    }

    // =============================================
    // PARENT PROCESS
    // =============================================
    else
    {
        printf("\n--- PARENT PROCESS ---\n");
        printf("Parent PID: %d\n", getpid());
        printf("Child PID: %d\n", pid);

        // Parent also has its OWN COPY of arr[]
        // Sorting here does NOT affect child's array
        sort(arr, n);
        printf("Parent sorted array: ");
        display(arr, n);

        // =============================================
        // ZOMBIE DEMONSTRATION
        // =============================================
        // Parent sleeps 5 seconds WITHOUT calling wait()
        // Child already called exit(0) → child is DEAD
        // But parent hasn't acknowledged it → child becomes ZOMBIE
        // ZOMBIE = dead child whose record still exists in process table
        printf("\nParent sleeping for 5 seconds...\n");
        printf("During this time, child becomes a ZOMBIE.\n");
        fflush(stdout);
        sleep(5); // ← During these 5 seconds, child is a ZOMBIE

        // Check zombie state via /proc/<pid>/stat → should show Z
        printf("\n[ZOMBIE CHECK BEFORE wait()]\n");
        show_state(pid); // Expected: state = Z

        printf("\n[ps BEFORE wait() - child should be Z / defunct]\n");
        fflush(stdout);
        system("ps -l"); // On Linux: shows child as Z <defunct>

        // =============================================
        // wait() - Parent acknowledges child's death
        // =============================================
        // wait() does two things:
        // 1. Reads child's exit status
        // 2. REMOVES zombie entry from process table
        printf("\nParent is calling wait()...\n");
        wait(NULL); // ← Zombie is removed here

        // Now zombie should be gone
        printf("\n[ZOMBIE CHECK AFTER wait()]\n");
        show_state(pid); // Expected: no process entry found

        printf("\n[ps AFTER wait() - zombie removed]\n");
        fflush(stdout);
        system("ps -l"); // On Linux: child PID no longer visible
        printf("Zombie child has been removed.\n");

        // =============================================
        // ORPHAN DEMONSTRATION
        // =============================================
        // ORPHAN = child process whose PARENT dies before it
        // Orphan is automatically adopted by init (PID 1)
        printf("\n--- ORPHAN PROCESS DEMONSTRATION ---\n");
        fflush(stdout);

        pid_t orphan_pid = fork(); // Create another child

        if (orphan_pid < 0)
        {
            perror("Fork failed");
            return 1;
        }

        // =============================================
        // ORPHAN CHILD PROCESS
        // =============================================
        if (orphan_pid == 0)
        {
            printf("Orphan child created.\n");
            printf("Child PID: %d\n", getpid());
            printf("Initial Parent PID: %d\n", getppid()); // Parent's PID (e.g. 341)

            // Child sleeps for 10 seconds
            // During this time, parent will exit() and die
            printf("Child sleeping for 10 seconds...\n");
            fflush(stdout);
            sleep(10); // ← Parent dies during this sleep

            // After waking up → parent is already dead
            // init (PID 1) has adopted this child → child is now ORPHAN
            printf("\nAfter parent terminates:\n");
            printf("Child PID: %d\n", getpid());
            printf("New Parent PID: %d\n", getppid()); // Should now be 1 (init)
            printf("Child is now an ORPHAN process.\n");

            printf("\n[ps in orphan child - PPID should now be 1]\n");
            fflush(stdout);
            system("ps -l"); // On Linux: shows PPID = 1 for this child
        }

        // =============================================
        // ORPHAN PARENT - Dies immediately
        // =============================================
        else
        {
            printf("Orphan demonstration parent PID: %d\n", getpid());

            // Parent exits immediately WITHOUT waiting for child
            // Child is still sleeping → child becomes ORPHAN
            printf("Parent is terminating immediately...\n");
            exit(0); // ← Parent dies here → child becomes ORPHAN
        }
    }

    return 0;
}

------------------------------------------------------------------------------
PROCESS AND FORK()
------------------------------------------------------------------------------

Q1. What is a process?
Ans: A process is a program that is currently executing.

Q2. What is a system call?
Ans: A system call is a mechanism through which a user program requests
     services from the operating system kernel. Examples: fork(), wait(),
     read(), write(), exec().

Q3. What is fork()?
Ans: fork() is a system call used to create a new child process from an
     existing parent process.

Q4. What does fork() return?
Ans: -1 : Process creation failed.
     0 : Currently executing in child process.
     >0 : Currently executing in parent process.
     The returned value is the child's PID.

Q5. Which header file is required for fork()?
Ans: #include <unistd.h>

Q6. What is PID?
Ans: PID stands for Process ID. It is a unique identification number assigned
     to a process.

Q7. Which function returns the current process ID?
Ans: getpid() returns the PID of the current process.

Q8. Which function returns the parent process ID?
Ans: getppid() returns the PID of the parent process.

Q9. Does fork() create an exact copy of the parent?
Ans: Yes, the child initially inherits the parent's address space. However,
     parent and child have separate address spaces. Linux commonly uses Copy-
     on-Write (COW) for efficiency.

Q10. Does the parent execute first or the child?
Ans: There is no guaranteed execution order. The OS scheduler decides which
     process executes first.

Q11. What happens to variables after fork()?
Ans: Both processes initially have the same variable values. Changes made in
     one process do not normally affect the other.

Q12. Why do we use pid == 0?
Ans: fork() returns 0 in the child process. It helps us identify whether the
     current process is a child.

------------------------------------------------------------------------------
WAIT() SYSTEM CALL
------------------------------------------------------------------------------

Q13. What is the purpose of wait()?
Ans: wait() makes the parent wait until one of its child processes terminates
     and collects its termination status.

Q14. Which header file is required for wait()?
Ans: #include <sys/wait.h>

Q15. What happens if the parent does not call wait()?
Ans: If the child terminates, it can remain as a zombie process until its
     termination status is collected.

Q16. Difference between wait() and waitpid()?
Ans: wait() waits for any one child process. waitpid() can wait for a specific
     child process. waitpid() provides more control.

Q17. What does wait(NULL) mean?
Ans: It waits for a child process to terminate but does not store the child's
     exit status.

Q18. Can a parent have multiple child processes?
Ans: Yes, a parent can create multiple child processes using multiple fork()
     system calls.

------------------------------------------------------------------------------
ZOMBIE PROCESS
------------------------------------------------------------------------------

Q19. What is a zombie process?
Ans: A zombie is a process that has completed execution but whose parent has
     not collected its termination status.

Q20. Why does a zombie process exist?
Ans: The OS retains some process information so that the parent can collect
     the child's exit status.

Q21. How are you demonstrating a zombie in your program?
Ans: Using sleep(5), the parent delays calling wait(). Meanwhile, the child
     terminates and can become a zombie.

Q22. How do you identify a zombie process in Linux?
Ans: Using the command: ps -l Look for Z in the process state column. It may
     also appear as <defunct>.

Q23. How do you remove a zombie process?
Ans: The parent calls wait(NULL). This collects the child's termination status
     and removes its zombie entry from the process table.

Q24. Can you kill a zombie using kill -9?
Ans: No. A zombie has already terminated. Its parent must collect its exit
     status using wait() or the process must be reparented and reaped.

------------------------------------------------------------------------------
ORPHAN PROCESS
------------------------------------------------------------------------------

Q25. What is an orphan process?
Ans: An orphan is a child process whose original parent terminates while the
     child is still executing.

Q26. How are you demonstrating an orphan in your program?
Ans: The child executes sleep(10), while the parent executes exit(0) and
     terminates immediately. The child continues executing without its
     original parent.

Q27. Who adopts an orphan process?
Ans: Normally, the init/systemd process (PID 1) adopts it. However, a
     configured child subreaper may adopt it instead.

Q28. Difference between zombie and orphan?
Ans: ZOMBIE:
     1. Child has terminated.
     2. Parent has not collected its exit status.
     3. Process state is Z.
     4. Removed after being reaped.
     ORPHAN:
     1. Child is still executing.
     2. Original parent has terminated.
     3. Adopted by another process.
     4. Continues normal execution.

Q29. Can an orphan process become a zombie?
Ans: Yes. If an orphan terminates and its new parent has not collected its
     exit status, it can become a zombie.

Q30. Is an orphan process harmful?
Ans: No. An orphan is not necessarily harmful. Linux handles orphan processes
     through reparenting.

------------------------------------------------------------------------------
QUESTIONS ABOUT YOUR CODE
------------------------------------------------------------------------------

Q31. Why are you using fflush(stdout)?
Ans: It flushes buffered output so that messages are displayed before
     processes execute further. It is particularly useful around fork() and
     system().

Q32. Why are you using /proc/<PID>/stat?
Ans: Linux provides the /proc virtual filesystem. It contains information
     about running processes. We read this file to identify the process state.

Q33. Why are you using strrchr() instead of strchr()?
Ans: strrchr() finds the last occurrence of a character. The process name in
     /proc/<PID>/stat is enclosed in parentheses and can contain spaces or
     parentheses. Therefore, we find the last closing parenthesis to locate
     the process state correctly.

AIM:
  Implement the bounded-buffer Producer-Consumer problem using POSIX threads,
  counting semaphores (empty, full) and a mutex.

----- producer_consumer.c ---------------------------------------------------
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <semaphore.h>
#include <unistd.h>

#define BUFFER_SIZE 5

int buffer[BUFFER_SIZE];

int in = 0;
int out = 0;

sem_t empty;
sem_t full;
pthread_mutex_t mutex;

void *producer(void *arg)
{
    int item;

    while (1)
    {
        item = rand() % 100;

        sem_wait(&empty);

        pthread_mutex_lock(&mutex);

        buffer[in] = item;
        printf("Producer produced: %d at position %d\n", item, in);

        in = (in + 1) % BUFFER_SIZE;

        pthread_mutex_unlock(&mutex);

        sem_post(&full);

        sleep(1);
    }

    return NULL;
}

void *consumer(void *arg)
{
    int item;

    while (1)
    {
        sem_wait(&full);

        pthread_mutex_lock(&mutex);

        item = buffer[out];
        printf("Consumer consumed: %d from position %d\n", item, out);

        out = (out + 1) % BUFFER_SIZE;

        pthread_mutex_unlock(&mutex);

        sem_post(&empty);

        sleep(2);
    }

    return NULL;
}

int main()
{
    pthread_t producer_thread, consumer_thread;

    sem_init(&empty, 0, BUFFER_SIZE);
    sem_init(&full, 0, 0);

    pthread_mutex_init(&mutex, NULL);

    pthread_create(&producer_thread, NULL, producer, NULL);
    pthread_create(&consumer_thread, NULL, consumer, NULL);

    pthread_join(producer_thread, NULL);
    pthread_join(consumer_thread, NULL);

    sem_destroy(&empty);
    sem_destroy(&full);
    pthread_mutex_destroy(&mutex);

    return 0;
}

AIM:
  Implement the Dining Philosophers problem using POSIX threads and
  semaphores, avoiding deadlock by making even and odd philosophers pick
  chopsticks in a different order.

==============================================================================

----- dining.cpp ------------------------------------------------------------
#include <iostream>
#include <pthread.h>
#include <semaphore.h>
#include <unistd.h>

using namespace std;

#define MAX 100

sem_t chopstick[MAX];
int N;

void* philosopher(void* arg)
{
    int id = *(int*)arg;

   
        cout << "Philosopher " << id << " is thinking..." << endl;

        sleep(1);

        if (id % 2 == 0)
        {
            sem_wait(&chopstick[(id + 1) % N]);

            cout << "Philosopher " << id
                 << " picked RIGHT chopstick" << endl;

            sem_wait(&chopstick[id]);

            cout << "Philosopher " << id
                 << " picked LEFT chopstick" << endl;
        }
        else
        {
            sem_wait(&chopstick[id]);

            cout << "Philosopher " << id
                 << " picked LEFT chopstick" << endl;

            sem_wait(&chopstick[(id + 1) % N]);

            cout << "Philosopher " << id
                 << " picked RIGHT chopstick" << endl;
        }

        cout << "Philosopher " << id
             << " is eating..." << endl;

        sleep(2);

        sem_post(&chopstick[id]);
        sem_post(&chopstick[(id + 1) % N]);

        cout << "Philosopher " << id
             << " finished eating" << endl;
    

    return nullptr;
}

int main()
{
    pthread_t philosophers[MAX];
    int id[MAX];

    cout << "Enter number of philo: ";
    cin >> N;

    if (N < 2 || N > MAX)
    {
        cout << "Invalid number of philo" << endl;
        return 1;
    }

    for (int i = 0; i < N; i++)
    {
        sem_init(&chopstick[i], 0, 1);
    }

    for (int i = 0; i < N; i++)
    {
        id[i] = i;
        pthread_create(&philosophers[i], nullptr, philosopher, &id[i]);
    }

    for (int i = 0; i < N; i++)
    {
        pthread_join(philosophers[i], nullptr);
    }

    for (int i = 0; i < N; i++)
    {
        sem_destroy(&chopstick[i]);
    }

    return 0;
}

  1. Deadlock         - two or more processes wait indefinitely for resources held by each other.
  2. Starvation       - a process waits indefinitely because other processes repeatedly get
                        the resources it needs.
  3. Mutual Exclusion - only one philosopher can hold a particular chopstick at a time.

AIM:
  Implement the Banker's Algorithm: calculate the Need matrix and use the
  safety algorithm to decide whether the system is in a SAFE state and print
  the safe sequence.

#include <iostream>
using namespace std;

int main() {
    int max[10][10], need[10][10], alloc[10][10];
    int avail[10], completed[10], safeSequence[10];

    int p, r;
    int count = 0;

    cout << "Enter the no. of processes: ";
    cin >> p;

    cout << "\nEnter no. of resources: ";
    cin >> r;

    if (p > 10 || r > 10 || p <= 0 || r <= 0) {
        cout << "\nMaximum 10 processes and 10 resources are allowed.\n";
        return 1;
    }

    for (int i = 0; i < p; i++)
        completed[i] = 0;

    cout << "\nEnter the Allocation Matrix:\n";
    for (int i = 0; i < p; i++) {
        cout << "For process P" << i + 1 << ": ";
        for (int j = 0; j < r; j++) {
            cin >> alloc[i][j];

            if (alloc[i][j] < 0) {
                cout << "\nError: Allocation cannot be negative.\n";
                return 1;
            }
        }
    }

    cout << "\nEnter the Max Matrix:\n";
    for (int i = 0; i < p; i++) {
        cout << "For process P" << i + 1 << ": ";
        for (int j = 0; j < r; j++) {
            cin >> max[i][j];

            if (max[i][j] < alloc[i][j]) {
                cout << "\nError: Max cannot be less than Allocation for P"
                     << i + 1 << ".\n";
                return 1;
            }
        }
    }

    cout << "\nEnter the AVAILABLE resources: ";
    for (int i = 0; i < r; i++)
        cin >> avail[i];

    for (int i = 0; i < p; i++) {
        for (int j = 0; j < r; j++) {
            need[i][j] = max[i][j] - alloc[i][j];
        }
    }

    cout << "\n\nNeed Matrix:\n";

    for (int i = 0; i < p; i++) {
        cout << "P" << i + 1 << ": ";

        for (int j = 0; j < r; j++)
            cout << need[i][j] << " ";

        cout << endl;
    }

    while (count < p) {
        bool found = false;

        for (int i = 0; i < p; i++) {
            if (completed[i] == 0) {
                bool canRun = true;

                for (int j = 0; j < r; j++) {
                    if (need[i][j] > avail[j]) {
                        canRun = false;
                        break;
                    }
                }

                if (canRun) {
                    cout << "\nP" << i + 1 << " can run." << endl;
                    cout << "00000000000000000000 THE NEW AVAILABLE IS 00000000000000000000" << endl;
                    for (int j = 0; j < r; j++) {
                        avail[j] += alloc[i][j];

                        cout << avail[j] << " ";
                    }

                    completed[i] = 1;
                    safeSequence[count] = i + 1;
                    count++;

                    found = true;
                }
            }
        }

        if (!found)
            break;
    }

    if (count == p) {
        cout << "\n\nThe system is in a SAFE state.\n";

        cout << "Safe sequence: < ";

        for (int i = 0; i < p; i++) {
            cout << "P" << safeSequence[i];

            if (i != p - 1)
                cout << " -> ";
        }

        cout << " >\n";
    }
    else {
        cout << "\n\nThe system is in an UNSAFE state.\n";
        cout << "No complete safe sequence exists.\n";
    }

    return 0;
}

Q46. Difference between safe state and unsafe state?
Ans: Safe state: At least one safe sequence exists. Unsafe state: No safe
     sequence exists.

Q47. Difference between deadlock avoidance and detection?
Ans: Avoidance checks before granting resources. Detection checks whether
     deadlock has already occurred.

Q48. Is Banker's Algorithm applicable to multiple instances of resources?
Ans: Yes. It is designed for systems with multiple instances of each resource
     type.

Q49. What is the main disadvantage of Banker's Algorithm?
Ans: Every process must declare its maximum resource demand in advance, and
     resource requirements should be known.

Q50. Is Banker's Algorithm used in real operating systems?
Ans: It is an important theoretical algorithm for deadlock avoidance, but
     general-purpose operating systems do not typically use it for all
     resource allocation.

AIM:
  Two independent processes communicate using two FIFOs. Process 1 (p1.c)
  accepts sentences and sends them to Process 2 through FIFO 1. Process 2

{
    int fd1, fd2;

    char buffer[1000];

    text[0] = '\0';

        printf("FIFO 1 created successfully.\n");
    } else  {

        printf("Failed to create FIFO 2");
        
    }
    
    
    printf("\nEnter sentences:\n");
    printf("Enter END to finish:\n");
    
     while (1)
    {
        fgets(buffer, sizeof(buffer), stdin);

        if (strcmp(buffer, "END\n") == 0)
            break;
            
        if (strlen(text) + strlen(buffer) < sizeof(text)) {
            strcat(text, buffer);
        } else {
            printf("Warning: Buffer full! Stopping input.\n");
            break;
        }
    }

    write(fd1, text, strlen(text) + 1);

#include <stdlib.h>

int main()
{
    int fd1, fd2;
    char text[1000];
    char buffer[1000];

    int characters = 0;
    int words = 0;
    int lines = 0;
    int in_word = 0;

        printf("FIFO 1 created successfully.\n");
    }

        printf("FIFO 1 already exists. Reusing it.\n");
    }
    else {
        printf("Failed to create FIFO 1\n");
        exit(1);
    }

    if (mkfifo("fifo2", 0666) == 0) {
        printf("FIFO 2 created successfully.\n");
    } 
    else if (errno == EEXIST) {
        printf("FIFO 2 already exists. Reusing it.\n");
    }
    else {
        printf("Failed to create FIFO 1\n");
        exit(1);
    }

    printf("Process 2 is running and waiting for data...\n");
    
    fd1 = open("fifo1", O_RDONLY);
    n = read(fd1, text, sizeof(text) - 1);
    text[n] = '\0';
    close(fd1);
    
        for (int i = 0; text[i] != '\0'; i++)
    {
        characters++;

        if (text[i] == '\n')
            lines++;

        if (isspace((unsigned char)text[i]))
        {
            in_word = 0;
        }
        else if (in_word == 0)
        {
            words++;
            in_word = 1;
        }
    }
    
    FILE *file = fopen("output.txt", "w");
    if (file == NULL) {
        perror("Failed to create output.txt");
        exit(1);
    }
    
    
    fprintf(file, "--- Received Sentences ---\n%s", text);
    fprintf(file, "--------------------------\n");
    
    
    
    fprintf(file, "Number of characters = %d\n", characters);
    fprintf(file, "Number of words = %d\n", words);
    fprintf(file, "Number of lines = %d\n", lines);
    fclose(file);
    
    
        fd2 = open("fifo2", O_WRONLY);
    file = fopen("output.txt", "r");
    if (file != NULL) {
        while (fgets(buffer, sizeof(buffer), file) != NULL)
        {
            write(fd2, buffer, strlen(buffer));
        }
        fclose(file);
    }
    close(fd2);

    printf("Analysis written to output.txt and sent back successfully.\n");
    return 0;
}

HOW TO COMPILE / RUN

  Enter sentences:
  Enter END to finish:
  hello world
  this is OS practical
  END

OUTPUT in Terminal 1 (p1):
  FIFO 1 created successfully.
  FIFO 2 created successfully.

  Enter sentences:
  Enter END to finish:
  hello world
  this is OS practical
  END

  Output received from Process 2:
  --- Received Sentences ---
  hello world
  this is OS practical
  --------------------------
  Number of characters = 33
  Number of words = 6
  Number of lines = 2

OUTPUT in Terminal 2 (p2):
  FIFO 1 already exists. Reusing it.
  FIFO 2 already exists. Reusing it.
  Process 2 is running and waiting for data...
  Analysis written to output.txt and sent back successfully.

FILE CREATED: output.txt  (same text as the "Output received" part above)

HOW THE NUMBERS COME OUT
  characters = 12 ("hello world\n") + 21 ("this is OS practical\n") = 33  (spaces and \n are counted)
  words      = 2 + 4 = 6
  lines      = number of '\n' characters = 2

KNOWN LIMITATIONS (good to mention in viva)
  1. p1.c calls read() on FIFO 2 only ONCE. p2.c sends the file line by line with many
     write() calls, so on some systems p1 may print only the FIRST chunk
     (e.g. only "--- Received Sentences ---"). Fix: read in a loop in p1.c:
         printf("\nOutput received from Process 2:\n");
         while ((n = read(fd2, buffer, sizeof(buffer) - 1)) > 0) {
             buffer[n] = '\0';
             printf("%s", buffer);
         }
     (This replaces the single read(), the  buffer[n] = '\0';  line and the printf("%s", buffer);.)
  2. If p2 is started first, p1 prints "Failed to create FIFO 1/2" because p1 does not check
     errno == EEXIST. It is harmless - the existing FIFOs are used.
  3. In p2.c the second error message (line 40) says "FIFO 1" but it belongs to FIFO 2 (typo).
  4. A last line typed without pressing Enter is not counted as a line (lines count '\n' only).

BASIC IPC CONCEPTS
------------------------------------------------------------------------------

Q1. What is IPC?
Ans: IPC stands for Inter-Process Communication. It allows two or more
     processes to communicate and exchange data with each other.

Q2. What is FIFO?
Ans: FIFO stands for First In First Out. It is a named pipe used for
     communication between independent processes.

Q3. Why is FIFO called a named pipe?
Ans: Because it has a name in the filesystem, unlike an ordinary unnamed pipe.

Q4. What is the purpose of FIFO?
Ans: FIFO allows independent processes to exchange data.

Q5. What is full duplex communication?
Ans: Full duplex means communication in both directions.

Q6. Why are two FIFOs used in your program?
Ans: FIFO 1 sends sentences from Process 1 to Process 2. FIFO 2 sends the
     analysis result from Process 2 back to Process 1.

Q7. Can FIFO communicate between independent processes?
Ans: Yes. FIFO is specifically useful for communication between independent
     processes.

Q8. Does FIFO store data permanently?
Ans: No. FIFO transfers data through the kernel. Its filesystem entry
     persists, but transferred data is not stored as an ordinary file.

Q9. What is a named pipe?
Ans: A named pipe is a special file used as a communication channel between
     processes.

Q10. What are the different IPC mechanisms?
Ans: 1. Pipes
     2. FIFOs
     3. Message Queues
     4. Shared Memory
     5. Semaphores
     6. Sockets

------------------------------------------------------------------------------
PIPE VS FIFO
------------------------------------------------------------------------------

Q11. What is the difference between pipe and FIFO?
Ans: Pipe:
     1. Also called unnamed pipe.
     2. Usually used between related processes.
     3. Created using pipe().
     4. Does not have a filesystem name.
     FIFO:
     1. Also called named pipe.
     2. Can communicate between independent processes.
     3. Created using mkfifo().
     4. Has a filesystem name.

Q12. Which is better for independent processes?
Ans: FIFO, because independent processes can access it using its filesystem
     name.

Q13. Is FIFO bidirectional?
Ans: A FIFO is normally used in one direction. Two FIFOs can be used to
     achieve bidirectional communication.

Ans: mkfifo() is a system call used to create a named pipe.

Q15. What does 0666 mean in mkfifo()?

     subject to umask.

Q16. What is open()?
Ans: open() opens a file or FIFO and returns a file descriptor.

Q17. What is a file descriptor?
Ans: A file descriptor is an integer used by the OS to identify an opened file

Ans: It opens a file or FIFO in write-only mode.

Ans: It opens a file in read and write mode.

Ans: read() reads data from a file descriptor or FIFO.

Q22. What is write()?
Ans: write() writes data into a file descriptor or FIFO.

Q23. What is close()?
Ans: close() closes an opened file descriptor.

Q24. What is unlink()?
Ans: unlink() removes a filesystem entry such as a FIFO.

Q25. Does open() block for FIFO?

Q26. What happens if the FIFO already exists?

Q27. What is EEXIST?

  PRACTICAL 7: FULL-DUPLEX COMMUNICATION USING TWO PIPES (parent <-> child)        @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@

AIM:
  Parent and child communicate using two unnamed pipes. The parent sends a
  file name to the child through pipe1; the child opens the file, reads it and
  sends the contents back to the parent through pipe2, and the parent displays
  them.

----- pipe.c ----------------------------------------------------------------
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <fcntl.h>
#include <string.h>

int main()
{
    int pipe1[2], pipe2[2];
    pid_t pid;
    char filename[100];
    char buffer[1024];
    int fd, n;

   
    if (pipe(pipe1) == -1 || pipe(pipe2) == -1)
    {
        perror("pipe");
        exit(EXIT_FAILURE);
    }

    
    pid = fork();

    if (pid < 0)
    {
        perror("fork");
        exit(EXIT_FAILURE);
    }

    if (pid > 0)   
    {
        printf("i am in parent\n");
        close(pipe1[0]);   
        close(pipe2[1]);   

        
        printf("Enter file pathname: ");
       
        fgets(filename, sizeof(filename), stdin);

       
        filename[strcspn(filename, "\n")] = '\0';

     
        write(pipe1[1], filename, strlen(filename) + 1);
        close(pipe1[1]);

    
        printf("\nContents of file:\n");

        while ((n = read(pipe2[0], buffer, sizeof(buffer) - 1)) > 0)
        {
            buffer[n] = '\0';
            printf("%s", buffer);
        }

        close(pipe2[0]);

        wait(NULL);
    }
    else  
    {
        close(pipe1[1]);   
        close(pipe2[0]);   
        
        
       sleep(2);
        n = read(pipe1[0], filename, sizeof(filename) - 1);

        if (n <= 0)
        {
            perror("read");
            exit(EXIT_FAILURE);
        }
         printf("i am in child\n");
        
        filename[n] = '\0';
        close(pipe1[0]);

      
        fd = open(filename, O_RDONLY);

        if (fd == -1)
        {
        
            perror("open");
            close(pipe2[1]);
            exit(EXIT_FAILURE);
        }

     
        while ((n = read(fd, buffer, sizeof(buffer))) > 0)
        {
       
            write(pipe2[1], buffer, n);
        }

        close(fd);
        close(pipe2[1]);

        exit(EXIT_SUCCESS);
    }

    return 0;
}

             PRACTICAL 8: DISK SCHEDULING - SSTF, SCAN AND C-LOOK              @@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@

AIM:
  Write a program to simulate the disk scheduling algorithms SSTF, SCAN and
  C-LOOK. For each algorithm display the order in which the tracks are served,
  the total head movement and the average seek length. (Assumption: the head
  first moves towards HIGHER-numbered tracks.)


==============================================================================
SECTION 1: CODE
==============================================================================

----- disk.c ----------------------------------------------------------------
#include <stdio.h>
#include <stdlib.h>

static int cmp(const void *a, const void *b)
{
    return *(const int *)a - *(const int *)b;
}

static void report(const char *name, const int *order, int cnt, int head, int n)
{
    int total = 0, cur = head;

    printf("\n=== %s ===\nSeek order: %d", name, head);
    for (int i = 0; i < cnt; i++)
    {
        total += abs(order[i] - cur);
        cur = order[i];
        printf(" -> %d", cur);
    }
    printf("\nTotal head movement = %d\n", total);
    printf("Average seek length = %.2f\n", (float)total / n);
}

static void sstf(const int *req, int n, int head)
{
    int *order = malloc(n * sizeof(int));
    int *used = calloc(n, sizeof(int));
    int cur = head;

    for (int k = 0; k < n; k++)
    {
        int best = -1;
        for (int i = 0; i < n; i++)
            if (!used[i] && (best == -1 || abs(req[i] - cur) < abs(req[best] - cur)))
                best = i;
        used[best] = 1;
        order[k] = req[best];
        cur = req[best];
    }
    report("SSTF", order, n, head, n);
    free(order);
    free(used);
}

static void scan(const int *s, int n, int head, int size)
{
    int *order = malloc((n + 1) * sizeof(int));
    int cnt = 0, i = 0;

    while (i < n && s[i] < head) i++;

    for (int j = i; j < n; j++) order[cnt++] = s[j];
    if (cnt == 0 || order[cnt - 1] != size - 1)
        order[cnt++] = size - 1;
    for (int j = i - 1; j >= 0; j--) order[cnt++] = s[j];
    report("SCAN (towards higher tracks first)", order, cnt, head, n);
    free(order);
}

static void clook(const int *s, int n, int head)
{
    int *order = malloc(n * sizeof(int));
    int cnt = 0, i = 0;

    while (i < n && s[i] < head) i++;

    for (int j = i; j < n; j++) order[cnt++] = s[j];
    for (int j = 0; j < i; j++) order[cnt++] = s[j];
    report("C-LOOK (towards higher tracks first)", order, cnt, head, n);
    free(order);
}

int main(void)
{
    int n, head, size;

    printf("Enter total number of tracks (e.g. 200): ");
    if (scanf("%d", &size) != 1 || size < 2) { printf("Invalid size\n"); return 1; }

    printf("Enter number of requests: ");
    if (scanf("%d", &n) != 1 || n < 1) { printf("Invalid count\n"); return 1; }

    int *req = malloc(n * sizeof(int));
    printf("Enter the request queue (%d tracks): ", n);
    for (int i = 0; i < n; i++)
    {
        if (scanf("%d", &req[i]) != 1 || req[i] < 0 || req[i] >= size)
        {
            printf("Invalid request (must be 0 to %d)\n", size - 1);
            return 1;
        }
    }

    printf("Enter initial head position: ");
    if (scanf("%d", &head) != 1 || head < 0 || head >= size)
    {
        printf("Invalid head position (must be 0 to %d)\n", size - 1);
        return 1;
    }

    sstf(req, n, head);

    qsort(req, n, sizeof(int), cmp);
    scan(req, n, head, size);
    clook(req, n, head);

    free(req);
    return 0;
}

Q1. What is disk scheduling?
Ans: Disk scheduling is the technique used by the operating system to decide
     the order of disk I/O requests.

Q2. Why is disk scheduling required?
Ans: To reduce disk head movement, seek time and improve overall performance.

Q3. What is a disk track?
Ans: A track is a circular path on the disk surface where data is stored.

Q4. What is a sector?
Ans: A sector is a subdivision of a disk track.

Q5. What is seek time?
Ans: Seek time is the time required for the disk head to move to the required
     track.

Q6. What is head movement?
Ans: It is the distance travelled by the disk head between tracks.

Q7. What is SSTF?
Ans: SSTF stands for Shortest Seek Time First. It selects the request closest
     to the current head.

Q8. How does SSTF work?
Ans: It calculates the distance of every pending request from the current head
     and selects the minimum distance.

Q9. What is the main advantage of SSTF?
Ans: It generally reduces total head movement compared with FCFS.

Q10. What is starvation?
Ans: Starvation occurs when a request waits for a very long time because other
     requests keep getting priority.

Q11. What is SCAN?
Ans: SCAN is also called the Elevator Algorithm. The head moves in one
     direction, services requests, reaches the disk boundary and reverses
     direction.

Q12. Why is SCAN called the Elevator Algorithm?
Ans: Because it behaves like an elevator moving in one direction and then
     reversing direction.

Q13. What is the advantage of SCAN?
Ans: It provides more uniform service compared with SSTF.

Q14. What is C-LOOK?
Ans: C-LOOK is a circular disk scheduling algorithm. It services requests in
     one direction and then jumps to the lowest pending request.

Q15. What is the main advantage of C-LOOK?
Ans: It avoids unnecessary movement to the physical disk boundary.

Q16. What is the difference between SCAN and C-LOOK?
Ans: SCAN goes to the disk boundary before reversing. C-LOOK goes only as far
     as the last request and then jumps to the first pending request.

Q17. What is the difference between SSTF and SCAN?
Ans: SSTF selects the nearest request. SCAN services requests in one
     direction.

Q18. What is the difference between C-LOOK and C-SCAN?
Ans: C-SCAN travels to the physical boundary. C-LOOK travels only to the last
     pending request.

Q19. What is the formula for total head movement?
Ans: Total movement = Sum of absolute differences between consecutive head
     positions.

Q20. What is the formula for average seek length?
Ans: Average seek length = Total head movement / Number of requests.

Q21. What is the purpose of abs()?
Ans: It returns the absolute value of an integer.

Q22. Why is qsort() used?
Ans: It sorts the disk request queue in ascending order.

Q23. What is cmp()?
Ans: It is a comparator function used by qsort().

Q24. Why is malloc() used?
Ans: It dynamically allocates memory.

Q25. What is calloc()?
Ans: It dynamically allocates memory and initializes the allocated bytes to
     zero.

Q26. Why is used[] required in SSTF?
Ans: It identifies which requests have already been serviced.

Q27. Why is the request queue sorted for SCAN?
Ans: So that requests can be serviced in increasing or decreasing track order.

Q28. Why is the initial head position important?
Ans: It determines the starting point for calculating head movement and
     selecting requests.

Q29. What is the direction assumed in this program?
Ans: The initial head moves towards higher-numbered tracks first, away from
     the spindle.

Q30. What is the maximum track number if disk size is 200?
Ans: 199, because track numbering starts from zero.

Q31. Does SSTF require sorting?
Ans: No. It searches all unserviced requests for the nearest one.

Q32. Does SCAN always produce minimum head movement?
Ans: No. Its main purpose is to provide systematic and relatively fair
     servicing.

Q33. Can SSTF cause starvation?
Ans: Yes. Requests far from the current head may wait for a long time.

Q34. Can SCAN reduce starvation?
Ans: Yes. It provides more predictable servicing than SSTF.

Q35. Does C-LOOK visit track 0 and the last track?
Ans: Not necessarily. It visits only requested tracks, unless those boundary
     tracks are requested.

Q36. What happens if the initial head is at the highest track?
Ans: The higher-direction part has no requests, and SCAN moves to the boundary
     before reversing.

Q37. Which algorithm is best among SSTF, SCAN and C-LOOK?
Ans: It depends on the request pattern and performance requirements. No
     algorithm is always best.

Q38. Which algorithm is also known as the Elevator Algorithm?
Ans: SCAN.

Q39. What is the purpose of free()?
Ans: It releases dynamically allocated memory.

Q40. What does static mean before a function?
Ans: It gives the function internal linkage, making it accessible only within
     the current source file.

Q41. What is the difference between total seek time and total head movement?
Ans: Head movement is measured in tracks. Seek time is measured in time units.

Q42. Why do we use higher-numbered tracks first here?
Ans: Because the problem specifies initial movement away from the spindle,
     assuming track 0 is nearest to it.

Q43. Does the C-LOOK jump count in total head movement?
Ans: Yes. The distance between the last higher request and the lowest pending
     request is included.

Q44. Does SCAN count movement towards the disk boundary?
Ans: Yes. Movement to the boundary is included.

Q45. What is the time complexity of SSTF in this code?
Ans: O(n^2), because every request selection scans the remaining request
     queue.

Q46. What is the time complexity of qsort()?
Ans: Typically O(n log n), though its exact worst-case behavior depends on the
     implementation.
